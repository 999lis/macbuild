团队方案

给开发团队的 Mac：构建机、runner、开发环境

你团队现在跑 iOS 构建，可能正在为同一台机器的算力付五倍价钱。 这一页不劝你买，先帮你算清楚账。

先算一笔账

GitHub 官方对 macOS runner 的计费是 $0.062 / 分钟（3-core 或 4-core）。 拖动下面的滑块，看你团队的实际成本。

每天构建次数20 次

指 CI 触发的 macOS 任务总数，含 PR 校验、主分支构建、上架打包。

单次构建时长15 分钟

从 checkout 到产物上传的总耗时。首次构建慢，之后有缓存会快一些。

需要的机器台数1 台

一台 Mac 串行跑构建，够用的上限大约是每天 30 次 × 15 分钟。超过就该加机器。

计算口径：GitHub Actions 按官方公布的 macOS runner 单价 $0.062/分钟 × 30 天计算，汇率按 1 USD ≈ 7.2 CNY。 自建 Mac 按共享线路 ¥799/月/台 计算，不含独立线路加价。以上未计入 GitHub 免费额度—— 免费额度对 macOS 构建来说很少，通常几天内用完，所以这里按全额计费更接近实际。

为什么差价这么大

GitHub Actions 的 macOS runner 按分钟计费，Linux 是 $0.006/分钟，macOS 是 $0.062/分钟—— 十倍。原因是 Apple 的虚拟化授权限制，GitHub 只能用 Mac 硬件跑 macOS，成本降不下来。

而一台 Mac mini 一旦买下来或租下来，它的算力是不按分钟计的。你跑 1 次和跑 100 次，成本一样。

所以差别不在「谁的机器便宜」，而在「计费方式」。 用量越大，按分钟计费越吃亏；固定月费越划算。

反过来说：如果你的构建量很小（比如一周只跑几次），按分钟计费反而更省。 上面计算器拉到最低会看到这一点——我们不建议小用量的人换自建。

自建 runner 要做什么

不需要重写 CI。只需要三步，配置一次。

① 在机器上装 Runner

从仓库的 Settings → Actions → Runners 拿到注册命令，在 Mac 上执行一次。之后机器会常驻在线等待任务。

② 改 workflow 的 runs-on

jobs:
  build:
    runs-on: self-hosted    # 原来是 macos-latest
    steps:
      - uses: actions/checkout@v4
      # 其余步骤不用改

③ 装好构建依赖

Xcode 版本、CocoaPods、Fastlane、证书与描述文件。这一步是一次性的，装好之后所有构建共用。

需要你注意的：自建 runner 意味着构建环境由你控制，也由你维护。 系统更新、Xcode 升级、依赖变更都需要你自己处理。我们负责机器的电力、网络和在线状态，不负责 CI 配置。

除了 CI，还能做什么

Claude Code 开发环境

给团队里每个人配一台独立环境，各自用自己的账号。不共享账号——共享是封号最主要的原因，见 账号风险说明。

App Store 上架打包

需要 macOS 环境做签名、归档、上传 App Store Connect。放在机房的好处是上传带宽稳定，不占开发机。

海外环境验证

出海团队需要海外 IP 做投放验证、支付通道测试、应用商店区域检查。德国是欧洲互联网枢纽，出口质量稳定。

长期运行的自动化任务

爬虫、监控、定时任务。这类需求的特点是「必须一直开着」，正好是机房环境相对办公室的优势——有 UPS、有稳定网络、不会因为停电或搬工位中断。

关于开票，需要提前说清楚

我们可以提供德国主体的商业发票（Rechnung）。但如果你所在的公司必须有增值税专用发票才能抵扣， 境外主体通常无法开具。

请在付款前确认这件事，不要等付完才发现财务过不了。 我们不希望出现「钱付了、票开不出、财务卡住」的情况——这对双方都是麻烦。

如果你的采购流程必须要可抵扣专票，直接告诉我们，我们会明确说当期能不能满足，不会先收钱再说做不到。

什么情况下你不该找我们

这一节是为了让你少花时间。

  • 构建量很小——一周只跑几次，GitHub Actions 按分钟计费更省，别换
  • 需要可抵扣的增值税专用发票——境外主体开不出，除非你已经确认过财务能接受境外发票
  • 要频繁用图形界面操作——远程桌面有延迟，视频剪辑、UI 设计这类工作不适合
  • 需要 GPU 训练——Mac mini 不是算力卡，训练模型请找别的方案
  • 要 Windows 环境——我们只有 macOS
  • 需要分钟级 SLA 与 7×24 值班——我们做不到，别买

如果你的需求不在这几条里，告诉我们团队规模和构建量， 我们会给你一个具体报价，包括「你这个量其实不用换」这种回答。

常见问题

自建 Mac runner 和 GitHub Actions 的 macOS runner 差多少？

GitHub 官方对 macOS 3-core 或 4-core runner 的计费是每分鐘 0.062 美元，约合每小时 3.72 美元。一台自建 Mac 按月固定收费，不按分钟计。以每天 20 次、每次 15 分钟的构建量计算，GitHub Actions 的月成本约 558 美元，折合人民币约 4000 元，而一台共享线路的 Mac 是 799 元每月。

自建 runner 需要自己维护吗？

需要配置一次，之后基本免维护。具体是在机器上装 GitHub Actions Runner 并注册到仓库或组织，之后 workflow 里把 runs-on 指向 self-hosted 即可。系统更新、依赖升级由你控制，我们负责机器的电力、网络与在线状态。

可以开票吗？

我们可以提供德国主体的商业发票（Rechnung）。需要提前说明的是：中国大陆企业若需要增值税专用发票用于抵扣，境外主体通常无法开具。如果你的采购流程必须要有可抵扣的专票，请在付款前与我们确认，我们会明确告知当期能否满足，不会先收钱再说做不到。

可以签合同吗？

可以。多台采购、长期合作都可以签服务合同，明确交付内容、可用性口径、故障响应方式与责任边界。合同条款以服务条款为基础，可以按团队需求补充。

多台有折扣吗？

有。三台起可以谈批量价，具体取决于台数、周期与线路类型。长周期（半年、年付）本身已有折扣，与批量价可以叠加商谈。

可以先试用吗？

可以先按月租一台验证。建议用真实的构建流水线跑一周，确认依赖能装、构建能过、上传 App Store Connect 正常，再决定是否扩大台数。不建议一上来就签年付。

机器在德国，对国内团队有影响吗？

对 CI 构建本身没有影响，因为构建是在远端跑的，只有拉取代码和上传产物走网络。对交互式操作有影响：SSH 命令行基本无感，图形界面有明显延迟。CI 场景不看界面，所以德国位置不是问题；但如果你的团队要频繁用远程桌面操作，体验会下降。
