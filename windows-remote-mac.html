Windows × macOS

Windows 远程 Mac：怎么连、能做什么、什么做不到

先说一个很多人不知道的事实：微软的远程桌面连不上 Mac。 macOS 没有 RDP 服务端。这篇讲清楚三种能用的方案、各自的实际体验， 以及在 Windows 上用 Xcode 到底是什么感觉。

看看套餐 → 远程 Mac 租赁怎么选

为什么 Windows 用户需要一台 Mac

Windows 在大部分开发场景下完全够用。但有几件事是 macOS 独占的，没有替代方案：

  • Xcode——只能在 macOS 上运行，没有 Windows 版
  • iOS 模拟器——只有 macOS 有
  • iOS / macOS App 签名与上架——codesign、Transporter 都是 macOS 工具
  • Swift / Objective-C 编译——工具链只在 macOS 上
  • 部分 CI 工具——Fastlane 的某些 action 依赖 xcodebuild
  • Safari 真机测试——Safari for Windows 2012 年就停了

过去的选择是「再买一台 Mac」。现在的选择多了：可以远程连一台别人维护的 Mac， 按需付费，不用一次性投入几千块。

三种能用的远程方案

方案一：VNC（Mac 自带屏幕共享）

macOS 系统设置里有个「屏幕共享」，本质是 VNC 协议。Windows 端装个 VNC 客户端 （TightVNC、RealVNC、UltraVNC）就能连。

优点：不需要在 Mac 上装任何东西，系统自带。

缺点：

  • 没有声音、没有麦克风
  • 剪贴板同步不可靠
  • 弱网下画面容易糊
  • 需要自己处理内网穿透（如果 Mac 不在同一局域网）

适合：临时看一下画面，或者你已经有 VPN 能把两台机器打通。

方案二：第三方远程工具（推荐）

主流的有 RustDesk（开源，可自建服务器）、ToDesk、 UU 远程、Parsec（低延迟，偏游戏优化）。

优点：

  • 不需要配置网络，装好输入设备码就能连
  • 支持声音、剪贴板、文件传输
  • 有画面压缩优化，弱网下比 VNC 好很多

缺点：

  • 需要两端都装客户端
  • 免费版通常有限速或时长限制
  • 走厂商中继服务器，数据经过第三方（RustDesk 可自建规避）

适合：绝大多数人的日常使用。

方案三：Tailscale + SSH / VNC

Tailscale 是一个基于 WireGuard 的虚拟内网工具。两端装上并登录同一账号后， 会拿到固定的内网 IP，之后不管在什么网络下都能直连。

优点：

  • 一旦配好，任何网络环境都能连（不需要公网 IP）
  • 点对点直连，不经过第三方中继（能打洞成功时）
  • 命令行用 SSH，图形界面再套 VNC，两个都能用

缺点：

  • 初次配置比第三方工具麻烦
  • 需要两端都装、都登录

适合：长期使用、在意稳定性和隐私的人。

能做什么，不能做什么

这一节说实话，避免你踩坑。

✅ 完全能做的

  • 写代码（任何编辑器都行，包括 Xcode）
  • 命令行编译、构建、打包（这些在远端执行，延迟无关）
  • Git 操作、CI 触发
  • iOS App 签名、上架 App Store
  • 跑 Claude Code 长任务
  • 看模拟器运行结果、点按操作

⚠️ 能做但体验打折的

  • 模拟器交互调试——200ms 延迟下拖拽、多点触控会卡顿
  • Interface Builder 拖控件——精度受影响
  • 滚动长文档或网页——有明显拖影

❌ 不适合的

  • 视频剪辑、3D 渲染这类需要实时预览的工作
  • 在线会议（摄像头 + 麦克风链路太长）
  • 需要精确时间感的操作（音频编辑、游戏）
  • 把远程 Mac 当主力机做全天图形界面工作

配置步骤（以 RustDesk + Tailscale 为例）

第一步：在 Mac 上允许远程访问

系统设置 → 通用 → 共享 → 打开「屏幕共享」和「远程登录」。

「远程登录」就是 SSH 服务。打开后你才能用命令行连。

第二步：装 Tailscale 组虚拟内网

Mac 和 Windows 两端都装 Tailscale，登录同一账号：

# macOS
brew install --cask tailscale

# Windows
winget install Tailscale.Tailscale

装好后在 Tailscale 后台能看到两台设备的 100.x.x.x 内网 IP。

第三步：Windows 端 SSH 连过去

ssh 用户名@100.x.x.x

建议配 SSH 免密和连接复用，减少握手开销： 

# ~/.ssh/config
Host mac
    HostName 100.x.x.x
    User 用户名
    ControlMaster auto
    ControlPath ~/.ssh/cm-%r@%h:%p
    ControlPersist 10m
    ServerAliveInterval 30

第四步：需要图形界面时开远程桌面

装 RustDesk（或 ToDesk），在 Mac 上打开，记下设备 ID 和密码， Windows 端输入即可连。

第五步：长任务用 tmux 保活

tmux new -s work
# 在里面跑任务
# Ctrl+B 然后按 D 断开，任务继续跑
# 下次 tmux attach -t work

这一步比什么都重要。不用 tmux 直接跑，SSH 一断进程就死了。

延迟对体验的实际影响

不同位置的机器，体验差别很大：

无法仅凭地区给出固定延迟保证。请根据自己的网络与任务类型确认是否适用。

判断标准：如果你 90% 的时间在终端里，200ms 完全没影响； 如果你 90% 的时间在图形界面，选 80ms 以内的机器。

常见问题

Windows 能用自带的远程桌面连 Mac 吗？

不能。微软的远程桌面（RDP）需要目标机器运行 RDP 服务端，而 macOS 没有内置 RDP 服务端。Mac 原生支持的是 VNC 协议（系统设置里的「屏幕共享」）。所以要么用 VNC 客户端，要么用 RustDesk、ToDesk、UU 远程这类第三方工具。

在 Windows 上用远程 Mac 能跑 Xcode 吗？

能。Xcode 是在远程 Mac 上运行的，你的 Windows 只是显示画面和发送键鼠输入。编译、签名、打包、上架 App Store 全都能做。但 iOS 模拟器的实时交互在 200ms 延迟下会卡顿，适合看结果和点按，不适合做交互调试。

延迟大概多少？

中国大陆境内 20–50ms，香港/新加坡 40–80ms，日本/韩国 60–120ms，马来西亚 180–220ms，欧美 200–350ms。SSH 和编译对延迟不敏感；拖窗口、滚网页、操作模拟器会明显感觉到。

有声音和麦克风吗？

VNC 协议不带音频，所以系统自带的屏幕共享只有画面，没有声音，剪贴板同步也不可靠。ToDesk、UU 远程、RustDesk 支持音频和剪贴板。需要完整多媒体支持（音频 + 麦克风 + 剪贴板），NoMachine 是社区口碑比较好的选择。

能传文件吗？

能。图形工具通常内置文件传输；命令行可以用 scp 或 rsync；也可以挂同步盘。如果只是传代码，直接用 Git 推拉最方便。

用 Windows 连远程 Mac 做 iOS 开发靠谱吗？

取决于工作方式。以写代码 + 命令行构建为主、只在需要时看模拟器，完全靠谱。重度依赖 Xcode 图形调试器、Interface Builder、Instruments 的话，延迟会明显影响效率，建议机器放近一点或直接用本地 Mac。
